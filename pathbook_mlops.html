Pathbook: the MLOps engagement

A book of numbered pages for the MLOps reference architecture. Read a page, pick a path, and each pick adds a module to the queue. At the end the book composes a build brief shaped to one client.

Working nameBook 0.2Runs the MLOps reference architecture v1.224 Oct 2026

A Pathbook turns an architecture into a menu. The consultant defines the architecture once; the book makes every part of it an optional module. A client operator chooses the modules that fit, answers a few plain questions, records the decisions each module needs, and approves a work queue. Nothing is added to scope except by a choice on the page — the operator holds scope, the book never widens it on its own. If the client already runs tools like MLflow, Weights & Biases, ClearML or ZenML, the book inventories them, asks how to treat each, and composes a gap plan — what the stack already satisfies and what must be added so each invariant holds — rather than a greenfield one.

What this page runs, and what it does not. This is the deterministic spine of the book, run in your browser: the pages, the picks, the dependency resolution, the gates, the contract hash and the compose step. It stops where the real Pathbook runner would hand each module to an agent to write the plan prose. So the brief you get here carries every module's boundary — its goal, its rules with the failure case (breaks_if) written out, its roles, its must-nots and its checks — which is the exact specification those agents would build against. No agent runs here, and nothing you enter leaves your browser.

Provenance. The needs questions below are a hand-drafted stand-in for the generation step and are not yet consultant-approved; the breaks_if lines are drafts; module dependencies were approved by the architecture owner on 2026-10-21.
